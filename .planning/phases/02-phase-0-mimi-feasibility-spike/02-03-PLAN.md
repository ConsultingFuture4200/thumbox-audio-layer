**Step 2 — Implement `spike/src/spike/probe_ffmpeg_pytorch.py`** (~80–120 lines):

Approach: spawn FFmpeg as a subprocess that decodes a WAV (or accepts a synthetic 30-second sine+noise input generated in-process and piped via stdin) into raw PCM streamed to stdout in 80 ms chunks at 24 kHz mono float32. The probe reads stdout chunk-by-chunk into numpy, transfers to a torch tensor on device, and times each step.

Concrete FFmpeg command (record this in the JSON output's `ffmpeg_command` field):
```
ffmpeg -hide_banner -loglevel error -re -i pipe:0 \
  -f f32le -ac 1 -ar 24000 \
  pipe:1
```

The `-re` flag enforces real-time pacing — critical for accurately measuring streaming overhead vs file-IO speed. Without `-re`, FFmpeg dumps the whole file as fast as possible and the probe measures bulk-IO, not streaming.

Per-chunk measurement loop:
```python
# pseudocode
chunk_bytes = 80ms * 24000Hz * 4 bytes/float = 7680 bytes
while True:
    t0 = time.monotonic_ns()
    raw = ffmpeg_proc.stdout.read(chunk_bytes)
    if not raw: break
    t1 = time.monotonic_ns()
    arr = np.frombuffer(raw, dtype=np.float32)
    t2 = time.monotonic_ns()
    tensor = torch.from_numpy(arr).to(device, non_blocking=False)
    torch.cuda.synchronize()  # ROCm-compatible
    t3 = time.monotonic_ns()
    # encode through Mimi for the second timing axis (encode latency, not handoff)
    codes = encode(model, fe, arr, sr=24000)
    torch.cuda.synchronize()
    t4 = time.monotonic_ns()
    handoff_us.append((t3 - t0) / 1000.0)  # ffmpeg read → tensor on device
    encode_ms.append((t4 - t3) / 1e6)     # encode-only
```

Discard first `n_warmup_chunks` measurements. Compute p50/p90/p99 for both `handoff_us` and `encode_ms`.
